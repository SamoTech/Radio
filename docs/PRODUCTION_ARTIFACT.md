# حزمة الإنتاج والتحقق — Phase 1 / INFRA-3

تاريخ المراجعة: 2026-11-25. هذا وصف تنفيذ؛ دليل الإصدار الحي هو نتيجة verifier على SHA محدد، وليس وجود هذه الوثيقة.

## قائمة النشر

`scripts/stage_production.py` هو المصدر الواحد لقائمة الملفات العامة. لا نسخ متكرر لمجلدات المستودع: ملفات HTML العامة والقانونية وoffline، CSS، JavaScript والوحدات، manifest والأيقونات، robots وsitemap، بيانات المحطات وhead وmanifest والدلتا، بيانات SDR والانتشار والخريطة، وصفحات SEO ذات أسماء مقيدة في countries/genres/languages/. تُحفظ مجموعات التشخيص العامة الحالية احترازيًا؛ تغيير سياسة بياناتها خارج هذه المهمة. الملفات الاختيارية المعلنة مثل CNAME وads.txt و.nojekyll تحفظ إن وجدت. الرفع يسمح بالملفات المخفية داخل staging الصريح فقط، حتى لا يسقط .nojekyll المسموح به؛ لا يسمح بنسخ ملفات مخفية من المستودع.

تعديل ملف تشغيل أو إضافة اعتماد محلي جديد يتطلب تحديث القائمة واختباراته. الفاحص يراجع مراجع HTML/CSS والوحدات الثابتة وloadModule وService Worker SHELL والأيقونات ووجهات sitemap وrobots وسلسلة الدلتا والعد الفعلي للكتالوج. التحليل ساكن؛ الاعتمادات الديناميكية الجديدة تحتاج مراجعة صريحة، ولا يدّعي اكتشاف كل JavaScript اعتباطي.

يُرفض الملف المطلوب الناقص، والمسار المتجاوز، والرابط الرمزي في الملف أو الآباء، وأسماء ملفات غير معتمدة، ومؤشرات مفاتيح خاصة وتوكنات شائعة. هذا يكمل GitGuardian ولا يستبدله. لا تُنشر tests/fixtures أو scripts أو docs أو proxy أو AGENTS/ROADMAP/README أو إعدادات التطوير. لا تعديلات على الملفات المتتبعة أثناء staging. المخرج يجب أن يكون خارج شجرة المصدر، غائبًا أو فارغًا؛ لا حذف تلقائي لمجلد غير فارغ. ترتيب الملفات والصلاحيات والتوقيت ثابت، والبايتات متكررة.

## وصف الإصدار v2

`scripts/deployment_provenance.py` يستورد نفس `production_inventory(root)`؛ لا قائمة بصمات مستقلة. يضيف إلى المخرج `build-info.json` فقط، دون بصمة ذاتية. الحقول الدقيقة:

| الحقل | الدلالة |
|---|---|
| schema_version | 2 |
| source_commit | SHA كامل من checkout الفعلي |
| service_worker_cache | القيمة المقروءة من sw.js، حاليًا radio-atlas-v103 |
| catalog_version / catalog_count | إصدار manifest وعدد مطابق لصفوف الملف الكامل |
| asset_sha256 | قاموس المسارات المرتبة وبصمات SHA256 |
| asset_size_bytes | نفس مجموعة المسارات وأحجامها بالبايت |

لا timestamp متغير في الوصف: نفس الملفات ونفس SHA ينتجان نفس الوصف. وقت التشغيل والنشر محفوظ في GitHub Actions. يتحقق الإصدار من metadata ومجموعات المسارات والأحجام والبصمات المتوقعة محليًا قبل الثقة بوصف الإنتاج؛ المدخلات الناقصة أو الزائدة أو المفاتيح المكررة مرفوضة.

التحقق الشبكي يشغّل أربع قراءات متزامنة كحد أقصى، بقطع 64KiB بدل تحميل الكتالوج الكامل في الذاكرة. الحجم المتوقع المحلي هو سقف كل رد، وContent-Length يُفحص إن وجد؛ سقف الملف المحلي 64MiB، والوصف 1MiB. مهلة الطلب 12 ثانية والميزانية المشتركة الافتراضية480 ثانية، وبحد20 محاولة قراءة و540 ثانية للميزانية المختارة. يُلغى العمل المنتظر وتُنتظر القراءات الجارية عند الفشل. كل طلب له nonce جديد وno-cache/no-store وidentity encoding. الفشل الدائم والصلاحيات لا تُخفى؛ اختلاف النشر أو CDN يظل فشلًا بعد استنفاد الحدود.

## إعادة الإنتاج والتراجع

من checkout الإصدار المطلوب:

```bash
python3 scripts/stage_production.py --output /tmp/radio-atlas-public
python3 scripts/deployment_provenance.py stamp --root /tmp/radio-atlas-public --commit <full-sha>
python3 scripts/deployment_provenance.py verify --commit <same-full-sha> --attempts 20 --delay 6
python3 -m unittest discover -s tests -p 'test_*.py'
```

الـworkflow يرفع المخرج فقط، ويُمرّر descriptor من نفس المخرج إلى متحكم Pages، ثم يتحقق من checkout بنفس SHA بعد نجاح النشر. يجب اختيار مجلد مؤقت جديد لكل إعادة إنتاج. الرجوع: PR تصحيحي يعيد ملفات التشغيل للنسخة الجيدة أو يصلح staging، بنفس قائمة النشر والتحقق؛ لا يُعاد نشر جذر المستودع لإخفاء ملف ناقص ولا يُتجاوز اختبار فاشل.

## قياس نفس اللقطة

لقطة المصدر الأساسية `7e22c4f34f236c0e478942df41bc4d453820de9b`، كتالوج40 وعدد61,303، دون descriptor في الطرفين. خط الأساس يستخدم الملفات المتتبعة التي كان نشر الجذر يضمها، باستثناء .git/.github؛ لا يدخل أدوات QA المؤقتة أو pycache.

| القياس | نشر الجذر السابق | القائمة النظيفة |
|---|---:|---:|
| عدد الملفات | 277 | 204 |
| مجموع بايتات الملفات | 20,023,549 | 18,672,524 |
| tar ثابت | 20,244,480 | 18,831,360 |
| gzip ثابت | 4,187,094 | 3,744,795 |

اختبار PWA upgrade يكتب عاملين اصطناعيين إلى جذر checkout المحلي. عند خدمة staging منفصلًا، يلزم HTTP overlay اختباري لهذين المسارين فقط من checkout؛ لا تضفهما إلى حزمة الإنتاج. أول تشغيل دون overlay أعاد404 كما هو متوقع للملفات غير المنشورة، ثم نجحت9فحوص lifecycle كاملة مع overlay. بقية اختبارات المتصفح تعمل مباشرة على staging: العام21، Kiwi المسجّل، Studio49 وOpenWebRX52، والوصولية96.
